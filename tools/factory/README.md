# Станція заливки jaam_fusion

Готує плату fusion (JAAM 3 / JAAM 2 / JAAM) до відправки клієнту за замовленням із магазину: резервує пристрій
замовлення, заливає тестову прошивку `test_mode`, оператор проходить тест, плата сама завантажує останню робочу
прошивку по Wi-Fi (OTA). Клієнт, номер замовлення й тип потрапляють у реєстр адмінки самі.

```
вибір замовлення зі списку -> chip_id з MAC -> POST /api/factory/register (резерв одиниці)
  -> підтвердження оператора -> erase -> test_mode + NVS «factory» (замовлення, Wi-Fi станції, URL релізу, сервер даних)
  -> оператор проходить тест, довго тисне BTN1 -> NVS-налаштування + OTA релізу -> FT:OTA OK, FT:CLEANUP OK
  -> POST /api/factory/complete
```

## Підготовка (один раз)

1. `pip install -r tools/factory/requirements.txt` (esptool, pyserial, esp-idf-nvs-partition-gen).
2. Зібрати тестові прошивки: `pio run -e test_mode_jaam3 -e test_mode_jaam2 -e test_mode_jaam1`
   (тип замовлення визначає збірку: `JAAM3.3` -> `test_mode_jaam3`, `JAAM2` -> `test_mode_jaam2`,
   `JAAM1` -> `test_mode_jaam1`; станція бере `.pio/build/<env>/`). Інші типи станція не прошиває.
3. API-токен: адмін-панель -> «Акаунт» -> «API-токени». Prod і dev - різні панелі: `JAAM_FACTORY_TOKEN_PROD`,
   `JAAM_FACTORY_TOKEN_DEV` (порожній - запитає прихованим вводом; прапорця `--token` немає навмисно).
4. Wi-Fi станції (2.4 ГГц, з інтернетом): `FACTORY_WIFI_SSID`, `FACTORY_WIFI_PASS`. Плата завантажує по ньому
   прошивку й після OTA стирає ці дані.

Усе це можна покласти в `tools/factory/.env` (шаблон `.env.example`, у git не потрапляє).

## Заливка

```bash
python tools/factory/factory_flash.py --stage prod run
```

- Станція показує оплачені замовлення з вільними пристроями (JAAM3.3, JAAM2, JAAM1; найстаріші першими, з
  прізвищем клієнта). Виберіть замовлення (Enter = перше): станція резервує за платою одну одиницю, показує
  «Замовлення N, пристрій i з n» і просить підтвердити **до стирання плати**.
- На платі: пройдіть тест (стрічки, датчики, кнопки). Усе гаразд - **довго натисніть BTN1**: плата запише
  налаштування, завантажить прошивку й перезапуститься. Брак - введіть `f` і Enter у терміналі станції.
- `--stage prod|dev` обов'язковий: разом із ним змінюються адмінка й сервер даних, до якого підключиться плата
  (`ws.jaam.net.ua` / `dev-ws.jaam.net.ua`, плата пише його в налаштування `wshost`).
- Прошивка для OTA - останній реліз GitHub (`https://update.jaam.net.ua/<версія>`); `--firmware-version` чи
  `--firmware-url` перевизначають.
- `--order-number 1234 --hw-version JAAM3.3` - явний вибір без списку; `--no-order --hw-version JAAM2` - прототип без
  замовлення (сервер не викликається); `--no-erase` пропускає стирання.
- `--fake-chip DEADBEEF0001` - **лише `--stage dev`**: без плати проганяє серверну частину (список, резерв,
  `complete`/`release`); `--fake-fail` імітує брак. На prod станція відмовляє до будь-яких викликів.

### Що станція робить з одиницею замовлення

| Подія | Що станція робить | `unit_state` у звіті |
|---|---|---|
| `FT:OTA OK` і `FT:CLEANUP OK` | `complete` (3 спроби) | `flashed` (`complete_failed`, якщо адмінка не підтвердила) |
| `FT:OTA ERROR ...`, брак від оператора (`f`), відмова на підтвердженні | `release` (3 спроби) | `released` (`release_failed`, якщо адмінка не підтвердила) |
| Таймаут, втрата порту, Ctrl+C, `FT:CLEANUP FAIL` | **нічого**: плата могла вже отримати прошивку | `reserved_unknown` |

`reserved_unknown` і `release_failed` лишають одиницю зарезервованою: перевірте плату й звільніть одиницю на сторінці
«Пристрої замовлень» в адмінці. Результат OTA станція має побачити на живому порту: `FT:OTA OK` друкується до
перезавантаження, а робоча прошивка на `?` не відповідає. Тому порт не закривайте й кабель не висмикуйте, доки станція
не напише «ПРОЙДЕНО» або «БРАК».

## Відомі обмеження

- **chip_id коротший за 12 цифр.** Прошивка друкує його як `%04x%04x`, і друга половина не доповнюється до 8 цифр:
  у плати, чий MAC має нульовий четвертий байт, виходить 10-11 цифр. Адмінка приймає лише 12, тож станція відмовляє
  таким платам (приблизно кожна 256-та): зареєструйте їх вручну.
- `test_mode` збираються лише для класичного ESP32 (JAAM1/2/3); ESP32-S3/C3 станція відхиляє.
- OTA-клієнт `test_mode` не перевіряє сертифікат сервера (як і бойова прошивка).

Звіт кожної плати лежить у `factory_reports/` (у git не потрапляє). Тести станції: `pytest tools/factory`.
